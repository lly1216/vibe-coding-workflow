# vibe-coding-workflow · AI 开发全流程 Skill

一套**所有大模型通用**的 AI 编程工作流方法论（vibe coding），整理自系列教程视频《一天一个 vibe coding 小技巧》的三期内容。不绑定任何特定工具——Claude Code、Cursor、Codex、GLM、GPT 等，凡是能加载规则文件/Skill 的 AI 编程助手都能用。

> 核心思想：**立项与拆分不是在写文档，而是在给 AI 立规矩——前面把规则拆得越清楚，后面 AI 写代码越不容易跑偏。**

## 流程总览

**写代码之前（立地基和规矩）——前置四步：**

1. **立项 + 功能清单** —— 想清楚做什么，拆成一条条说得清清楚楚的功能
2. **选技术栈** —— 选最适合项目且 AI 最熟的，定了就不摇摆
3. **搭项目架构** —— 先搭最小可跑的架子，定下统一开发规约
4. **写 Agent 宪法** —— 写给 AI 的项目规矩，每次开工自动生效

**写代码之后（控执行）：**

5. **实施真源文档** —— 只拆当前大阶段，细到"能执行、能验收、有边界"
6. **分阶执行 + 验收** —— 防漂移开工指令框住 AI，每做完一块先验收再推进

## 安装方式

**方式一：作为 Skill 安装**（支持 skills 约定的工具）

把 `vibe-coding-workflow/` 整个文件夹复制到你的工具的 skills 目录。各工具目录不同，不确定就直接问你的 AI："把这份 Skill 安装到你会自动读取的位置。"例如部分常见位置：

- ZCode：`<项目>/.agents/skills/` 或 `~/.agents/skills/`
- Claude Code：`<项目>/.claude/skills/` 或 `~/.claude/skills/`

**方式二：作为规则文件/系统提示词**

把 `SKILL.md` 的内容粘贴到你所用工具的项目规则文件（如 `AGENTS.md`、`CLAUDE.md`、`.cursorrules` 等）或直接作为系统提示词使用。

## 四个核心提示词模板（速览）

1. **生成功能清单**：逐功能说明给谁用/输入/输出/角色权限/正常流程/异常边界；复杂功能单独成文+索引；**先不要写代码**
2. **拆分阶段**：第一阶段为核心流程 MVP，**先宏观规划、暂不细化技术**
3. **细化实施真源文档**：拆子阶段→步骤，逐步说明做什么/做到什么程度/怎么验证/暂时不做什么
4. **子阶段开工（防漂移）**：严格遵守宪法和真源文档，只实施当前子阶段，做完停下汇报，不自动进入下一个

完整原文见 `SKILL.md`。

## 十条硬规则（速览）

1. 需求没对清楚，不写代码
2. 技术栈定了不摇摆
3. 先搭最小可跑的架构，不全量写功能
4. AI 规则必须放在工具会自动读取的位置
5. 通用模板必须结合项目真实情况定制，禁止原样粘贴
6. 每个任务步骤都要能执行、能验收、有边界
7. 每做完一块先验收再推进，不自动进入下一块
8. 架构红线：业务可调，底层架构不许随手动
9. 一份文档只干一件事，引用关系连成一条线
10. 需求变更先回写文档再实施
