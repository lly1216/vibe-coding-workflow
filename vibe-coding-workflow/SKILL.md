# Vibe Coding 全流程（通用大模型版）

来源：系列教程视频的方法论整理。核心思想一句话：

> **立项与拆分不是在写文档，而是在给 AI 立规矩——前面把规则拆得越清楚，后面 AI 写代码越不容易跑偏。**

AI 写代码很快，瓶颈早已不在"敲代码"，而在需求是否清楚、规矩是否立好、执行是否可控。本流程就是把这些"麻烦事"变成固定步骤。

## 总流程

**写代码之前（立地基和规矩）——前置四步：**

1. **立项 + 功能清单** —— 想清楚做什么，拆成一条条说得清清楚楚的功能
2. **选技术栈** —— 选最适合项目且 AI 最熟的，定了就不摇摆
3. **搭项目架构** —— 先搭最小可跑的架子，定下统一开发规约
4. **写 Agent 宪法** —— 写给 AI 的项目规矩，每次开工自动生效

**写代码之后（控执行）：**

5. **实施真源文档** —— 只把当前要做的这个大阶段拆细，细到"能执行、能验收、有边界"
6. **分阶执行 + 验收** —— 用防漂移开工指令框住 AI，每做完一块先验收再推进

## 硬规则（任何阶段都适用，不省略）

1. **需求没对清楚，不写代码。** 只要有含糊，AI 就会脑补，补出来的往往不是用户要的。判断标准：每个功能都能说清谁用、输入输出、权限、正常流程、异常边界。
2. **技术栈定了不摇摆。** 前端今天 React 明天 Vue、后端今天 Python 明天 Go，每摇摆一次，地基就得重打一次。
3. **先搭最小可跑的架构，不一口气全量写功能。** 就像装修房子先立地基、框架、承重墙，不会一上来先装修某个房间。
4. **AI 规则必须放在工具会自动读取的位置才会生效。** 各工具的位置和文件名不同，不用死记，直接问 AI："请在当前工具会自动读取的位置，帮我创建 agent 宪法文件。"
5. **任何通用模板都必须结合当前项目的真实情况定制，禁止原样粘贴。** 通用模板里没有你的立项、功能清单和技术栈；AI 按你实际的语言、框架、业务做适配，宪法才真正管用。
6. **每个任务步骤都要能执行、能验收、有边界。** 不是越细越好，细到 AI 知道"做什么、做到什么算完成、哪些先不碰、怎么验证"即可。
7. **每做完一块先停下来汇报，验收通过再推进，不自动进入下一块。** 无论 AI 是自己停的还是被要求汇报的，都先验收再往下走。
8. **架构红线：业务细节可以调，底层架构不许随手动。** 判断不了就先让 AI 做影响评估；非动不可时先暂停、讨论、评估、再定方案，严禁"先满足需求再说"。
9. **一份文档只干一件事，文档之间的引用关系连成一条线。** 不什么都塞进一个文档（自己找不着，AI 也抓错重点），也不到处乱引用。
10. **需求变更先回写文档，再实施。** 聊天里临时冒出来的想法不算正式变更，先落到"真源"文档里，AI 才有据可依。

## 使用方式：先判断用户在哪一步

- **全新想法** → 从第 1 步开始，按流程逐步引导，一步确认后再走下一步。
- **已有立项文档/部分资料** → 评估缺哪块，从缺的步骤切入，已有的帮助其对照细则自查。
- **已经在写代码但越写越乱** → 先停下补前置（至少补 Agent 宪法 + 当前阶段的实施真源文档），再继续开发。
- **只是一个小的改动/加一个小功能** → 不需要走全流程，但硬规则 1、7、8 仍然适用。

## 四个核心提示词模板

模板必须先按硬规则 5 定制（替换/补充项目真实信息），不要原样粘贴。

**① 生成功能清单**（第 1 步用）：

> 请根据立项文档，输出一份详细的功能清单。请逐个功能说明：这个功能给谁用、需要哪些输入、产生什么结果、涉及哪些角色和权限、正常流程是什么、有哪些异常和边界情况。如果某个功能特别复杂（比如角色权限系统），请把它单独写成一份文档，并在功能清单里留一个索引指过去。先不要写代码。

**② 拆分开发阶段**（第 2 步用）：

> 请根据功能清单将开发拆分为阶段。第一阶段需为核心流程的最小可用版本（MVP），并列出功能与排序逻辑。先进行宏观规划，暂不细化技术。

**③ 细化实施真源文档**（第 5 步用）：

> 请根据功能清单和阶段计划，细化当前大阶段，生成详细实施真源文档。先把这个阶段拆成几个子阶段，每个子阶段再拆成更小的步骤，逐条说明：每一步要做什么、做到什么程度、涉及哪些功能、用什么方式验证、暂时不做什么。

**④ 子阶段开工指令（防漂移）**（第 6 步每个子阶段开工前用）：

> 严格遵守 agent 宪法和实施真源文档，只实施当前子阶段，不要超出范围，做完后停下来汇报，不要自动进入下一个子阶段。

使用模板④时，同时把该阶段对应的实施真源文档路径发给 AI。这句话划的是两条边界：一条是它怎么做事（行动准则：宪法 + 真源文档），一条是这次具体做什么（任务范围：文档路径 + 单阶段指令）。

## 各阶段交付物自查

| 阶段 | 完成的标志 |
|---|---|
| 立项 | 有一份立项文档：核心业务目标、要做什么/不做什么 |
| 功能清单 | 每个功能过了"六问"（见细则 01）；复杂功能有专项文档 + 清单索引 |
| 阶段计划 | 每个大阶段都满足"某类用户能完整跑通、真的能用起来" |
| 技术栈 | 前端栈+组件库、后端语言+框架已成文，且不再改动 |
| 架构 | 有一个最小可跑的架子；前后端统一规约已成文 |
| Agent 宪法 | 规则文件放在工具自动读取的位置；内容结合了本项目真实情况 |
| 实施真源文档 | 当前大阶段拆成子阶段→步骤；每步能执行、能验收、有边界 |
| 执行验收 | 每个子阶段都通过了"验收三问"（见细则 03）才进入下一块 |
